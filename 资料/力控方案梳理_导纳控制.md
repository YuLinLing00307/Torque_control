# 力控方案梳理 · 导纳控制（Admittance Control）

> 背景：老师告知 ① 力矩传感器走 RS485，需外接主控板再与驱动器（电调）通信；② 力控算法思路为"把力矩映射成位置目标量，用 M（质量/二阶导）、B（阻尼）等系数解算，再交给位置环做 PID，以减小减速器对力矩的影响"，是个"A 开头的柔顺控制算法"。
> 结论：该算法 = **导纳控制（Admittance Control）**。企业已完成力矩传感器的集成与校准，算法设计与实现委托学校完成。

---

## 一、先确认算法名称：Admittance Control（导纳控制）

柔顺控制里有两个互为对偶的算法，一字之差、方向相反：

| | 阻抗控制 Impedance | **导纳控制 Admittance** |
|---|---|---|
| 物理含义 | 输入**运动**（位置/位移），输出**力** | 输入**力**（力矩），输出**位置** |
| 数学形式 | τ = M·Δq̈ + B·Δq̇ + K·Δq | Δq 由同一方程反解（力是输入） |
| 需要什么硬件 | 需要**高精度力矩控制**（电流→力矩要准） | 需要**高精度位置控制** + 力矩传感器 |
| 适用场景 | 直驱/准直驱关节、串联弹性执行器 | **高减速比关节（谐波/行星减速器）** |
| 本关节适配 | ✗ 不适合 | ✓ **正是老师描述的思路** |

老师说的"把力矩模拟成一个位置目标量，然后用这个位置目标量去做 PID"——这就是**导纳控制**的标准做法：**力是输入，位置指令是输出，位置环是执行层**。

### 数学形式

导纳模型本质上是给关节虚拟地装上一个"弹簧-质量-阻尼"系统：

```
M·Δq̈ + B·Δq̇ + K·Δq = τ_ext
```

- `τ_ext`：力矩传感器测到的外部力矩
- `M`：虚拟质量（惯量）系数
- `B`：虚拟阻尼系数
- `K`：虚拟刚度系数（K=0 → 完全柔顺/可自由拖动）
- `Δq`：由外力产生的位置偏移量

位置指令合成：

```
q_cmd = q0 + Δq        （q0 为名义位置，Δq 为柔顺偏移）
```

工程实现时把二阶方程**离散化**（双线性变换或二阶差分），在每个控制周期解出 `Δq[k]`，加上名义位置发给驱动器的位置环。注意 `M` 在参数表里的下限是 1（不能为 0），说明它同时是方程的系数，需防止除零。

### 为什么这台关节必须走导纳路线

MXBS-14 是 **100:1 谐波减速器 + 无力矩传感的驱动器**，两个特性直接判了"直接力矩控制"死刑：

1. **摩擦占主导**：谐波减速器摩擦力矩远大于惯性力矩，电流→输出力矩的关系被摩擦污染，开环力矩控制误差极大；
2. **传动非线性**：柔性变形、背隙、传动误差，让"电流→力矩"的模型非常难建。

而**位置控制**恰好是这台驱动器的强项：双编码器（输入端 17bit + 输出端 19bit 多圈）闭环，位置环运行 20kHz，精度和稳定性都有保证。

**所以导纳控制的核心价值就是：把"难做的力控问题"转换成"好做的位置控制问题"**——用高精度的位置环当执行器，把力控的难点（摩擦、间隙）隔离在外层算法里用 M/B/K 参数去调。这正是老师说的"减小减速器对力矩的影响"。

## 二、重要发现：驱动器固件里已经有这套算法了

我把参数全表挖了一遍，发现驱动器**内置了完整的力控/导纳功能**，不是"只有位置控制"：

| 功能 | 参数 | OD 索引 | 默认值 | 说明 |
|---|---|---|---|---|
| **导纳 K** | Force Position Admittance K | 0x3592:01 | 0 | **相当于劲度系数**（参数表原文） |
| **导纳 B** | Force Position Admittance B | 0x3592:02 | 0 | **相当于阻尼系数** |
| **导纳 M** | Force Position Admittance M | 0x3592:03 | 1 | **相当于质量系数**（下限 1） |
| 导纳单位 | Force Position Admittance Unit Index | 0x35FC | -3 | 单位指数，-3 即 10^-3 量级 |
| 阻抗 K/B/M | Force Position Impedance K/B/M | 0x3588:01/02/03 | 0/0/1 | 阻抗版（同一套公式的另一方向） |
| **力控模式** | Force Control Mode | 0x3590 | 0 | **1=电流控制模式，2=位置控制模式** ← 对应导纳 |
| **力传感器数据来源** | Force Sensor Type | 0x358F | 0 | **0=当前电流（无力传感器估算）、1=ADC1、2=ADC2、3=扩展通道** |
| 力控周期 | Force Control Cycle | 0x3591 | 1 | 外层力控环的周期设置 |
| 力传感器滤波 | Force Sensor LPF Cutoff Frequency | 0x3593 | 0 | 力传感器低通截止，抗噪声用 |
| 传感器零点 | Force Sensor Sampling Offset | 0x3594 | 0 | 当前值 = 上次值 − 偏移（零点校准用） |
| 传感器方向 | Force Sensor Direction | 0x3595 | 1 | 0x01 正 / 0xFF 负 |
| 力控搜索速度 | Force Control Search Speed | 0x3658 | 0 | 力控接触搜索速度 |
| 力控力矩补偿 | Force Torque Compensation Enable | — | 0 | 补偿表 |

**这意味着有两条技术路线可选**（需要和老师确认走哪条）：

- **路线 A（用驱动器内置）**：力矩传感器接到驱动器的"扩展通道"（`Force Sensor Type = 3`），驱动器内部跑导纳环 → 学校工作变成**标定 + 参数整定（K/B/M）+ 上层调度**
- **路线 B（学校自研，老师描述的那种）**：力矩传感器接外接主控板，**导纳算法跑在主控上**，主控通过 CAN 给驱动器下发位置指令 → 驱动器只做执行器

老师说"外接主控板……主控也可以拿来当上位机……和电调通信下发指令就能驱动电机"，指向的是**路线 B**。

> 💡 **强烈建议**：即使走路线 B，也先把驱动器的内置导纳（路线 A）跑起来当**对照基线**。一来能快速验证算法可行性、感受 M/B/K 的物理直觉，二来可以对比自研实现的效果，这是很好的实验设计思路，也能写进报告。

## 三、硬件链路梳理

老师描述的链路：

```
力矩传感器 ──RS485──> 外接主控板 ──(可选:上传)──> 电脑上位机(企业软件)
                          │
                          └──CAN/CANopen──> 驱动器(电调) ──> 电机 + 谐波减速器 ──> 关节输出
```

关键点：
- **RS485 只是物理层**，上层协议很可能是 Modbus RTU（本驱动器本身就支持 Modbus，默认 115200bps、节点 ID=1），也可能厂家自定义。**必须先拿到传感器的通信协议文档**。
- 主控要**同时**做两件事：轮询读传感器（RS485）+ 周期性下发位置指令（CAN）。这两个通信的时序设计是整个系统的关键。
- 如果也要实时上传电脑看波形，主控还需要一条上行链路（USB-CDC / UART / 再一路 CAN），注意别把控制周期拖慢。

## 四、实时性与 200–300Hz 带宽预算（这是成败关键）

老师强调的"行业水平 200–300Hz"，指的是**外层力控环的更新频率**。整条链路上任何一环慢了，整体就达不到。延迟预算大致如下：

| 环节 | 典型耗时 | 是否瓶颈 |
|---|---|---|
| 力矩传感器采样 + RS485 传输 | **未知，必须实测** | ★最大不确定性 |
| 主控读传感器 + 导纳解算 | 几十 μs（STM32 足够） | 否 |
| CAN 下发指令（1Mbps，CANopen 同步周期 1ms） | 0.2~1ms | 可能 |
| 驱动器位置环 | 20kHz（0.05ms） | 否 |

**要达到 200~300Hz（周期 3.3~5ms），整链路延迟必须控制在 1~2ms 以内。**

⚠️ **你现在最该做的第一件事：量出力矩传感器的实际数据更新率。** 如果传感器内部只有 100Hz 刷新（很多工业传感器确实如此），那 300Hz 力控就是纸上谈兵——这时候要么找厂家改刷新率，要么用观测器/预测算法补偿。这个数字直接决定项目可行性，越早确认越好。

## 五、分阶段实施路线

| 阶段 | 目标 | 产出 |
|---|---|---|
| **0. 硬件打通** | 拿到传感器协议文档；主控 RS485 读取成功；串口打印/上位机显示数据 | 能实时看到力矩数值 |
| **1. 传感器标定验证** | 挂砝码/外力加载 → 检查线性度、零点漂移、噪声、更新率 | 标定报告（企业已校准，需复验+拿到系数） |
| **2. 打通 CAN 控制** | STM32 发 CiA402 指令驱动电机（先用位置模式/CSP） | 能用自己主控驱动电机走位置 |
| **3. 算法离线验证** | PC/Simulink 按 M/B/K 参数仿真，输入录制的传感器数据，检查稳定性和输出位置指令 | 算法原型 + 参数整定经验 |
| **4. 上机联调** | 闭环跑起来：K 从大（硬）到小（柔顺）逐步试；M 下限 1 防止解算发散；B 加阻尼 | 关节能被人手推动且跟随柔顺 |
| **5. 性能测试** | 正弦扫频测力控带宽，对标 200~300Hz 目标 | 带宽测试曲线（这是核心指标） |

**你的优势正好用得上**：阶段 0/2 是 RS485 + CAN 收发，都是你熟的嵌入式活（CAN 有 RM 基础，RS485 比 CAN 还简单）；真正的难点在阶段 3/4 的控制理论部分——这里建议找师兄一起，老师也提到"建模请教师兄"。

## 六、需要确认的事（按优先级）

**立刻要问清的（阻塞项）：**
1. **力矩传感器型号与通信协议**：Modbus RTU 还是自定义？波特率/数据位/校验/寄存器映射？数据格式（int16/int32/浮点）？
2. **传感器刷新率（Hz）** —— 直接决定 200~300Hz 能否实现
3. **传感器量程、安装位置**：测的是关节输出力矩还是反作用力矩？安装在减速器输出端？
4. **你手上这台到底是 N 款还是 T 款**：型号码 `M-XB-S-14-100-B-S-C-N` 的最后一位 N = 无扭矩传感器，但老师说有传感器。要么是 T 款，要么传感器是后加的——**去看铭牌确认**（参数表里 `Force Sensor Type` 默认 0 = 用电流估算，说明"无传感器"是默认方案）
5. **主控板选型**：有没有指定？STM32 哪个系列？有无现成板子？

**稍后要问的：**
6. 企业的**校准系数、零点处理、温度漂移**方案——传感器已校准，这些数据必须拿到
7. 驱动器的 **EDS 文件 / CANopen 通信手册**（自己发 SDO/PDO 要用）
8. 目标指标的具体定义：200~300Hz 是指力控环频率？还是力跟踪带宽（-3dB）？这两个含义不同，测试方法也不同
9. 企业**为什么没直接用驱动器内置的导纳控制**？（他们只用内置功能的话，可能已经踩过坑，能省你很多时间）

## 七、安全红线

1. 力控模式下关节会**主动运动**（外力推动时跟随），调试时人、线缆、工装都要让开运动范围；
2. 导纳参数**先给 M 足够大 + B 足够大**（惯量大、阻尼足）再调 K，直接上小阻尼会剧烈振荡；
3. `M` 下限是 1，别设 0（方程退化/发散）；
4. 上电前确认传感器零点（`Force Sensor Sampling Offset`），零点漂了会持续输出错误的力矩指令，导致关节"自己跑"；
5. 第一步先**架空空载**（不接触任何东西）验证"读数为零时应保持静止"。
