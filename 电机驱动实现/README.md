# 从零把 MXBS-14 转起来 · 最小路径

> 前提：只用现有资料（指导书 + ServoHost 源码 + EDS），**不需要向企业再要任何协议文档**。

---

## 一、先搞清楚：模组引出的是哪两种接口

指导书第 3 页"接口分布"给的 8pin 排针定义（`CAN/RS485 通讯接口`）：

| PIN | 信号 | 说明 |
|---|---|---|
| 1 | **STO_IN** | 安全转矩关断输入 ⚠️ 不接 = 电机绝不输出力矩 |
| 2 | **STO_COM** | STO 公共端（接对应地） |
| 3 | CANL | CAN 差分负 |
| 4 | CANH | CAN 差分正 |
| 5 | GND | 信号地 |
| 6 | DBG_485A | **调试用 485（ServoHost 走这条）** |
| 7 | DBG_485B | 调试用 485 |
| 8 | GND | 信号地 |

所以有两条互相独立的路径，**协议完全不同**：

| | 路径 A：485 调试口 | 路径 B：CAN 口 |
|---|---|---|
| 引脚 | PIN6 / PIN7 | PIN3 / PIN4 |
| 协议 | 厂商私有 OD 读写帧（**不是** CANopen、**不是** Modbus） | 标准 CANopen CiA402 |
| 速率 | 921600 8N1 | 1000 kbps（出厂默认） |
| 上位机 | ServoHost 用的就是这条 | 上位机的 CAN 型机型 |
| 主机要求 | USB 转 485 模块，或 STM32 的 UART+485 | CAN 收发器 + 1000k 支持的 CAN 外设 |
| 适合 | **第一次点亮、单关节调试** | **组网、高频力控（PDO 周期同步）** |

> ⚠️ 注意：型号 `M-XB-S-14-100-B-S-C-N` 里的 **C = CAN 通讯**，但调试口仍然是 485。
> `ServoHost` 全部走 485（源码里 `serial_comm.py`：921600 + 64 字节帧 + CRC8，**没有 COB-ID、没有 NMT**）。
> 之前那份 CAN 速查表说的是 PIN3/PIN4 那条路，两条路不要混着用。

## 二、路径 A：PC + USB 转 485（最快，30 分钟内电机就能动）

### 硬件
- USB 转 RS485 模块（CH340/CP2102 + MAX485，十几块，自动收发方向的那种）
- 24V 或 48V 电源，XT30 插头

### 接线

```
模组 PIN6 (485A) ──── 模块 A
模组 PIN7 (485B) ──── 模块 B
模组 PIN5 (GND)  ──── 模块 GND        ← 必接，不接会偶发丢包
模组 PIN1 (STO_IN) ── 使能电平         ← 见下面第三节，最关键
模组 PIN2 (STO_COM)─ 对应地
```

### 跑

```bash
pip install pyserial
python pc_drive_485.py COM5
```

菜单里先按 `1` 读设备信息，能看到产品码和编码器分辨率，**说明通讯已经通了**；再按 `5` 让它正转一点。

### 帧格式（脚本里已实现，抄给你看）

```
发送：[header][idx_lo][idx_hi][sub][value...]  → 填充到 64 字节 → 追加 1 字节 CRC8 = 65 字节
      header = 0x23 写 / 0x40 读
接收：前 4 字节 echo，后 4 字节为数据（小端）
CRC8：右移，初值 0，多项式 0xB8（crit 在 utils/comm_functions.py:crc8）
```

实测帧（可直接拿串口助手对照）：

| 操作 | 前 8 字节 | CRC |
|---|---|---|
| 读 6041 状态字 | `40 41 60 00 00 00 00 00` | D5 |
| 写 6040 = 0x0006 | `23 40 60 00 06 00 00 00` | E9 |
| 写 6040 = 0x000F | `23 40 60 00 0F 00 00 00` | 58 |
| 写 6060 = 8 (CSP) | `23 60 60 00 08 00 00 00` | 2C |
| 读 6064 实际位置 | `40 64 60 00 00 00 00 00` | FF |

## 三、路径 B：STM32 + CAN（你的主战场）

### 接线

```
模组 PIN3 (CANL) ── 收发器 CANL
模组 PIN4 (CANH) ── 收发器 CANH
模组 PIN5 (GND)  ── 共地
```
收发器选 **SN65HVD230（3.3V）** 或 TJA1050（5V），别买成 5V 的给 3.3V MCU 用。

**终端电阻**：指导书明写"CAN 默认没有 120 欧电阻"。单节点、线短（<30cm）可以先不装；一旦上 1Mbps 或线变长，两端各加 120Ω，否则丢帧。

### 关键参数

| 项 | 值 |
|---|---|
| 波特率 | 1000 kbps（EDS 默认；实际值可读 OD 0x3519） |
| 节点 ID | 1（EDS 默认；实际值可读 OD 0x351A） |
| SDO 收发 | 发 `0x600+ID`，收 `0x580+ID` |
| SYNC | `0x080`，DLC=0 |

### 代码

`joint_can.c` / `joint_can.h` 直接加进工程：

```c
Joint_Init(&hcan1, 1);

if (HAL_CAN_Start(&hcan1) != HAL_OK) { /* 检查滤波器配置 */ }
HAL_CAN_ActivateNotification(&hcan1, CAN_IT_RX_FIFO0_MSG_PENDING);  /* 或用轮询版 */

if (!Joint_Enable())  { /* 读状态字看卡在哪一步 */ }
Joint_SetMode(MODE_PP);
Joint_MovePP(Joint_GetPosition() + 20000, 2000, 2000);
```

主循环 1ms 喂一次 `Joint_Heartbeat()`（发 SYNC）。

### 滤波器配置（CubeMX 容易漏）

```c
CAN_FilterTypeDef f = {0};
f.FilterBank = 0;
f.FilterMode = CAN_FILTERMODE_IDMASK;
f.FilterScale = CAN_FILTERSCALE_32BIT;
f.FilterIdHigh = 0x0000;
f.FilterIdLow = 0x0000;
f.FilterMaskIdHigh = 0x0000;   /* 全通，调试期先别过滤 */
f.FilterMaskIdLow = 0x0000;
f.FilterFIFOAssignment = CAN_RX_FIFO0;
f.FilterActivation = ENABLE;
HAL_CAN_ConfigFilter(&hcan1, &f);
```

## 四、三个会让你卡一整天的坑（按踩坑概率排序）

### 1. STO 不接，电机永远不使能 ⚠️

8pin 里 PIN1/PIN2 是 STO（Safe Torque Off）。**STO 没给有效电平，驱动器会拒绝进入 Operation enabled，你写 0x000F 也无效，状态字卡在 0x21/0x23。**

处理：`STO_COM` 接信号地，`STO_IN` 给驱动器规定的高电平（查铭牌或问师兄是 5V 还是 24V）。**先量一下 STO_IN 对 STO_COM 的电压**，不要凭猜。

> 如果仅调试阶段要临时旁路，务必先问师兄/老师——这是安全功能，不是普通使能。

### 2. 位置单位差 100 倍

EDS 里 `0x608F`（编码器分辨率）默认 4096、`0x6091`（齿轮比）默认 1:1，但你这台是 **17bit 电机端编码器 + 100:1 减速器**。

**必做**：先读 `0x608F:01/:02` 和 `0x6091:01/:02` 的实际值，脚本菜单 `1` 会打印"输出轴 1 圈 ≈ N 个单位"。**在拿到这个数之前，不要发大位置指令**，否则它会以 100 倍的速度冲出去。

### 3. 抱闸款（型号里的 B）

上电后抱闸需要释放才能转。若使能后电机有电流但轴不动、或有"哒"的一声后不转，先确认抱闸状态和释放逻辑。

## 五、上电顺序（固定下来别乱）

1. 主控/485 模块先上电，确认总线空闲
2. **接好 STO**，量电平
3. 上 24V/48V 主电
4. 读状态字，确认不是 Fault（`(sw & 0x4F) != 0x08`）
5. 使能 → 设模式 → 给**小**指令
6. 退出时先 `Shutdown 0x0006` 失能，再断主电

## 六、验证"通讯真的通了"的三个判据

| 判据 | 期望 |
|---|---|
| 读 `0x1000` 产品码 | `0x00004806`（X200A）说明是这块驱动板 |
| 读 `0x6041` 状态字 | 上电静置应为 `0x0250` 或 `0x0218`（`&0x6F` = 0x21 / 0x08） |
| 手动转一下输出轴（不通电） | `0x6064` 读数应单调变化 |

第 3 条最能说明问题：**位置反馈会动，就证明双向通讯完全正常**。

## 七、还需要实机读的 4 个值（文档里查不到，存在驱动器里）

| OD | 含义 | 用途 |
|---|---|---|
| 0x1000 | 产品码 | 验证驱动板型号 |
| 0x3519 | CAN 波特率 | 主控必须匹配 |
| 0x351A | 节点 ID | COB-ID 计算基准 |
| 0x608F / 0x6091 | 编码器分辨率 / 齿轮比 | 位置单位换算 |

这 4 个值读完，你的驱动层就没有未知量了。
